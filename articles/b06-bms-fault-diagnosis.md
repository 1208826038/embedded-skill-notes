# BMS 进阶（六）· BMS 故障诊断与预测性维护

> 你已有的 `10-bms-system.md` 在功能安全章提了过充/过放/过流/热失控诊断。这一章把它做厚：**传感器故障、单体断连、接触器粘连、绝缘故障、数据驱动诊断、RUL 预警**——这是 BMS 从"能用"到"可靠安全"的关键，也是 ISO 26262 诊断覆盖率（DC）的落地处。

---

## 一、诊断的层级

```
信号层：传感器读值是否合理（超限/卡死/跳变）
单体层：电压/温度/内阻异常、断连、微短路
电气层：电流异常、绝缘阻值低、接触器故障
系统层：通信丢失、算力异常、热失控预警
```

每层都要有**检测 + 判定 + 处理 + 记录（DTC）**。诊断结果进 DEM（ Diagnostic Event Manager），上报 UDS（`19` 读 DTC、`14` 清 DTC）。

---

## 二、典型故障与检测逻辑

### 2.1 电压采样故障（最难也最常见）

单体电压是被均衡/保护直接使用的核心量，故障后果严重：

- **采样超限/卡死**：读值长期 = 0 / 满量程 / 不变 → 判传感器失效。
- **偏差（bias）**：某芯读数系统性偏高/偏低（ADC 偏移、基准漂移）→ 用相邻芯一致性 + OCV 反推比对发现。
- **跳变（spike）**：单点突变后恢复 → 滑动中值滤波 + 跳变抑制，避免误触发保护。
- **多芯同步异常**：一片 AFE 通信异常 → 整片数据失效，应标记该片"不可信"并降级。

### 2.2 单体断连（Cell Disconnection）

某节采集线松脱/断线时，该芯电压读值会**随负载异常漂移**（开路后浮空，被邻近通过采样网络"拉"出非物理解）。检测：电压与电流/相邻芯相关性异常 + 充电时该芯电压不升反异常。

### 2.3 温度故障

NTC 断线 → 读值拉到满量程（如 5V 对应 −40℃，或 0V 对应极高）；NTC 短路 → 读值贴地。用"读值是否落在合理物理区间 + 多点一致性"判定。温度不可信时，**按最保守策略限功率**（宁错杀不放过）。

### 2.4 电流传感器故障

霍尔饱和（大电流削顶）、零点漂移、shunt 开路。检测：电流与电压变化不自洽（如电流=0 但 SOC 在变、或电压在掉）、双传感器（霍尔+shunt）交叉校验。

### 2.5 接触器故障（高压安全核心）

- **粘连（Weld/Stuck-ON）**：该断时断不开。检测：**预充前后电压逻辑**——断开指令下，测两端电压是否仍有高压（粘连标志）。危害极大（无法安全下电）。
- **卡死不吸合（Stuck-OFF）**：该通不通。检测：给闭合指令后主回路无电流/电压不建立。

> 工程铁律：任何上电/下电时序都先**校验接触器实际状态**（不只看驱动引脚，要看真实电压），这是 ASIL 要求的"诊断"。

### 2.6 绝缘故障（高压安全另一核心）

检测正负母线对车身地（Chassis）的绝缘电阻 `R_iso`。方法：**平衡桥/非平衡桥注入已知电阻，测分压**推算 `R_p`（正对地）与 `R_n`（负对地），取 `min(R_p,R_n)` 为绝缘阻值。

- 阈值：通常 `R_iso < 100Ω/V`（如 500V 系统 < 50kΩ）报警，< 更低则断高压。
- 你已有的 `10-bms-system.md` 讲了原理，这里强调**精度与抗扰**：注入信号频率要避开车载干扰，且需在"高压上电后周期性测"，因为绝缘电阻会随湿度/污染变化。

## 三、数据驱动故障诊断（行业新方向）

传统诊断靠"阈值 + 规则"，对**缓慢退化、隐性故障**不敏感。数据驱动补位：

- **特征提取**：从电压曲线、IC 曲线（dQ/dV）、内阻谱提取健康特征。
- **异常检测**：用正常工况建模（高斯过程、自编码器），偏离即报警（如某芯自放电异常 → 微短路前兆）。
- **分类器**：随机森林/SVM/NN 区分故障类型（断连 vs 微短路 vs 传感器偏差）。
- 多在**云端**训练，车端部署轻量推理或只上报特征。

## 四、预测性维护（PdM）与 RUL 联动

把第 3 章的 SOH/RUL 与诊断打通：

```
实时诊断（故障/异常） ─┐
                       ├─▶ 健康画像 ─▶ 预测性维护决策
SOH/RUL 趋势（退化）  ─┘        │
                                ▼
                  维保提醒 / 单体更换建议 / 功率降额
```

- 某单体 SOH 掉队明显 → 提示"该芯可能需更换"（梯次利用场景尤其有用）。
- 内阻持续上升 → 预警"低温/快充能力将下降"。

## 五、DTC 与 UDS 闭环

每个诊断项映射到 DTC（故障码），带**确认条件/去抖计数器**（防偶发误报）：

```
故障出现 → 计数器+1（达到阈值才确认置位 DTC）
故障消失 → 计数器-1（归零才清除）
```

确认后的 DTC 经 UDS `0x19` 可读、`0x14` 可清，并联动仪表报警 + 限功率/断高压。

## 六、常见坑

1. **温度不可信却继续正常用**：应降级为最保守策略，而非忽略。
2. **接触器只看驱动引脚不看真实状态**：驱动高 ≠ 真闭合，必须测电压校验，否则粘连漏检。
3. **绝缘检测被干扰误报**：注入频率选错 → 车载噪声耦合 → 频繁误断高压。需滤波 + 多次平均。
4. **诊断去抖缺失**：一次偶发尖峰就置 DTC，误报警扰民。必须确认计数器。
5. **只报不处理**：诊断到故障却不联动限功率/断高压，等于没诊断。诊断必须与执行器动作绑定。
6. **忽略一致性退化**：单体离散度缓慢增大是隐性故障前兆，只看单体阈值会漏。需监控离散度趋势。

## 七、面试要点

- **接触器粘连怎么检？** 下电指令下测主回路是否仍有高压（电压逻辑校验），不止看驱动引脚。
- **绝缘阻值怎么算？** 平衡/非平衡桥注入已知电阻，测分压推 R_p/R_n，取最小为绝缘阻值。
- **为什么温度故障要最保守？** 温度不可信→热保护失效→热失控风险，必须按最坏情况限功率。
- **传统诊断 vs 数据驱动？** 阈值规则对隐性/缓慢故障不敏感，数据驱动抓特征异常与趋势。
- **DTC 为什么要去抖计数器？** 防偶发干扰误置故障码，需持续确认才生效。
- **诊断覆盖率（DC）怎么体现？** 每个安全相关故障都有检测机制+处理逻辑，量化其覆盖比例，满足 ASIL。
