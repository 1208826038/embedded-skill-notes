# 操作系统进阶（四）· 内存管理：从分段到虚拟内存

> 内存是计算机最紧张的稀缺资源之一。本文讲清 OS 怎么在"有限的物理内存"上，给每个进程造出"独立且巨大的地址空间"：连续分配的历史、分页/分段/段页式、虚拟内存与缺页、TLB、页面置换算法（FIFO/OPT/LRU/Clock）、抖动与全局/局部置换，最后落到"页表怎么存"。内容与 `02-rtos-tuning.md` 第五章（MPU 栈保护）、`o01`（进程地址空间）呼应，并和仓库里的 MCU 内存布局（栈/堆/BSS）连成一条线。

---

## 一、内存管理要解决什么

1. **地址抽象**：程序用"逻辑地址（虚拟地址）"编程，不用关心物理在哪——重定位由 OS/MMU 完成。
2. **保护与隔离**：进程 A 不能踩进程 B 的内存（见 `o01` 地址空间隔离）。
3. **高效利用**：让有限物理内存装下更多进程（多道程序），并支持"部分装入"（程序比内存大也能跑）。
4. **共享**：多个进程共享同一份只读代码（如 `libc`），省内存。

---

## 二、连续内存分配（历史课）

### 2.1 单一/分区分配

最早：整个内存给一个程序（单道）；后来固定/可变分区，多个程序各占一块连续物理内存。

- **外部碎片**：可变分区反复分配释放后，内存出现许多不连续小空洞，总空闲够但凑不出一块连续的。
- **内部碎片**：分配单元（如页、或对齐到块）比实际申请大，浪费在块内。

连续分配的碎片问题催生了**非连续分配**——分页与分段。

---

## 三、分页（Paging）：最主流的非连续分配

### 3.1 基本思想

把**物理内存**和**虚拟地址空间**都切成固定大小的**页（Page，如 4 KB）**与**页框（Frame）**。虚拟页可映射到任意物理页框，**无需连续**。地址翻译：

```
虚拟地址 [ 虚拟页号 VPN | 页内偏移 offset ]
                ↓ 查页表
物理地址 [ 物理页框号 PFN | 页内偏移 offset ]
```

offset 直接拼上，VPN → PFN 由**页表**翻译。这样逻辑连续、物理离散，彻底消灭外部碎片（只剩页内内部碎片）。

### 3.2 页表与多级页表

页表记录每个 VPN→PFN 的映射，存在内存里。若地址空间大（如 64 位），一级页表会大到装不下，于是用**多级页表（如 x86 的 4 级、ARM 的 3/4 级）**——只展开实际用到的分支，省内存。

```
64 位虚拟地址（以 4 级为例）：
[ PML4 9 ][ PDPT 9 ][ PD 9 ][ PT 9 ][ offset 12 ]  （每级查一张表）
```

> 嵌入式呼应：MCU 一般**不用分页虚拟内存**（无 MMU，只有 MPU，见 `02` 第五章）。Cortex-A（跑 Linux）才有 MMU 做分页；Cortex-M（跑 RTOS）用的是 MPU 做"区域保护"而非地址翻译——这是 Linux 进程能隔离、RTOS 任务共享内存的根本硬件差异。

---

## 四、分段（Segmentation）

按**逻辑意义**划分可变长段：代码段、数据段、堆、栈、共享库段等。地址 = `[段号 | 段内偏移]`，段表记录每段的基址与限长。

- 优点：符合程序员直觉、便于共享（共享代码段）、保护（段级权限）。
- 缺点：段长可变 → **外部碎片**（要紧凑/压缩）。
现代 OS（如 x86）常**段页式结合**：先分段（提供逻辑视图与保护），每段内部再分页（消除碎片）。

---

## 五、虚拟内存（Virtual Memory）与按需调页

### 5.1 核心魔法

虚拟内存让进程以为自己有远超物理内存的连续空间。实现靠**按需调页（Demand Paging）**：进程启动时**只把需要的页装入内存**，访问到未装入的页时触发**缺页异常（Page Fault）**，OS 再把该页从磁盘（交换区/swap 或文件）调入。

```
进程虚拟空间 4GB，物理内存 1GB：
- 只有"常访问"的那部分页在物理内存里（工作集）
- 其余页在磁盘，用到才调入
```

这让"程序比内存大"成为可能，也支持了**进程间共享页**（如共享库只读页只装一份）。

### 5.2 缺页处理流程

1. CPU 访问虚拟地址，MMU 查页表发现"页不在内存"（有效位=0）。
2. 触发 Page Fault 异常，陷入内核。
3. 内核判断是否合法（地址在进程空间内？权限对？），不合法则 `SIGSEGV`（段错误）。
4. 合法则找一个空闲页框（没有就先按置换算法踢出一页），从磁盘读入，更新页表。
5. 返回用户态，重新执行那条指令。

> 缺页有快慢之分：**minor fault**（页已在内存只是没映射，如共享页首次访问）很快；**major fault**（要从磁盘读）很慢（毫秒级），是性能热点。

---

## 六、TLB：地址翻译的缓存

每次访存都要查页表（可能在内存多级），太慢。于是 MMU 有 **TLB（Translation Lookaside Buffer）**——页表项的硬件缓存。TLB 命中则直接得 PFN，几纳秒；未命中才走页表遍历（Page Table Walk）。

- **TLB 是与进程相关的**：进程切换要换页表（CR3/TTBR），旧 TLB 项失效 → **TLB shootdown**。这就是为什么 `o01` 说"进程切换比线程切换贵"。
- **ASID（Address Space ID）**：给 TLB 项打上进程标签，切换进程不必全刷 TLB，只刷其他 ASID 的项，减少抖动。

---

## 七、页面置换算法（Page Replacement）

内存满了、又要调入新页时，挑一页踢出去。目标：最小化**缺页率**。

### 7.1 OPT（最佳，理论下界）

置换"**将来最晚才被访问**"的页。缺页率最低，但**需要预知未来**，实际无法实现，只作比较基准。

### 7.2 FIFO

换**最早进入**的页。实现简单，但有 **Belady 异常**：分配更多页框反而缺页更多（反直觉）。

### 7.3 LRU（最近最少使用）

换**最久没被访问**的页。用"过去近似未来"，接近 OPT，性能好。实现：维护访问时间戳或栈，开销大；硬件常用"引用位"近似。

### 7.4 Clock（第二次机会）

LRU 的近似、工程实现：每页一个**引用位（R 位）**，环形链表组织。置换时扫描：
- R=1 → 清 0（给第二次机会），继续。
- R=0 → 选中踢出。
像时钟指针转圈，故名 Clock。比 LRU 省硬件，是很多 OS 的实际选择（Linux 的近似 LRU 用多链表 + 引用位演化）。

```
页框环: [A R=0]→[B R=1]→[C R=0]→[D R=1]
指针扫描到 B: R=1 → 清0, 跳; 到 C: R=0 → 踢 C
```

### 7.5 全局 vs 局部置换

- **局部**：只从缺页进程自己的页框里挑，进程间不抢。
- **全局**：从所有进程里挑（通常挑"最少使用"的），更灵活但可能让某进程页框被抢光而抖动。

---

## 八、抖动（Thrashing）

当**多道程序度过高**，每个进程的"工作集（Working Set，近期活跃页集合）"总和超过物理内存，系统陷入**疯狂缺页 ↔ 换入换出**的恶性循环，CPU 利用率骤降。

```
CPU 利用率
  ↑          ↘        （抖动区）
  |            ↘__
  |               \____
  +--------------------→ 多道程序度（并发进程数）
```

**工作集模型**：OS 跟踪每个进程的工作集，保证"常驻内存的页框 ≥ 工作集"，否则暂停/换出该进程，避免抖动。这是调度与内存管理的交汇点（呼应 `o02`）。

---

## 九、常见坑

1. **混淆虚拟地址与物理地址**：调试看到两个进程相同地址很正常（虚拟隔离），别当 bug；硬件看的是翻译后的物理地址。
2. **段错误（SIGSEGV）误判**：往往是野指针/栈溢出/访问已释放内存，不是"内存条坏了"。
3. **swap 导致假死**：内存不足时大量 major fault 从磁盘换页，系统卡顿——加内存或调 `swappiness`，或减少并发。
4. **TLB 没刷新**：自己改了页表（如写 OS/驱动）忘了刷 TLB，出现"翻译不一致"。
5. **Belady 异常误以为算法有 bug**：FIFO 真会越给越多页反而更差，换 LRU/Clock。
6. **MCU 上幻想用虚拟内存**：Cortex-M 无 MMU，只有 MPU，做不到按需调页；要隔离靠 MPU 区域而非分页。

## 十、面试要点

1. **分页 vs 分段？** 分页按固定大小、无外部碎片、对用户透明；分段按逻辑、可变长、有外部碎片、便于共享保护。
2. **虚拟内存怎么让程序比内存大？** 按需调页，只装活跃页，其余在磁盘，访问时缺页调入。
3. **TLB 是什么、为什么进程切换要刷它？** 页表缓存；进程切换换页表，旧 TLB 项失效（或用 ASID 避免全刷）。
4. **页面置换算法对比？** OPT 最优不可实现；FIFO 有 Belady 异常；LRU 近似最优但贵；Clock 是 LRU 的廉价近似。
5. **什么是抖动？怎么避免？** 工作集总和超内存导致疯狂换页；用工作集模型保证常驻页 ≥ 工作集。
6. **多级页表为什么省内存？** 只展开实际使用的地址分支，未用的高阶项不占空间。
7. **为什么 RTOS 不用虚拟内存？** MCU（Cortex-M）无 MMU，只有 MPU 做保护不做翻译；RTOS 任务共享物理地址空间，切换不换页表、开销低。
