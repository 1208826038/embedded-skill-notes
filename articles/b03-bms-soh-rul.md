# BMS 进阶（三）· SOH 健康度与 RUL 剩余寿命估计

> SOC 告诉你"现在剩多少电"，SOH 告诉你"电池还健康吗、能撑多久"。质保、残值、梯次利用全靠它。这是 BMS 里**最容易被低估、却商业价值最高**的一块。

---

## 一、什么是 SOH（State of Health）

行业常用两个口径，二者正相关但不等价：

- **容量法**：`SOH_cap = Q_max / Q_nominal`。新电池 100%，衰减到 80% 通常视为"寿命终点（EOL）"——这是车厂质保阈值（8 年/12 万公里/80% 常见）。
- **内阻法**：`SOH_r = R_nominal / R_current`（或 `(R_current - R_new)/R_new`）。内阻随老化上升，≈ 对应容量下降。

> 实务：两者都算，交叉验证。容量法直观但难测准（要满充放），内阻法好测但受温度影响大。

---

## 二、为什么会老化：两大机理

1. **SEI 膜增长（Solid Electrolyte Interphase）**：负极表面持续生成固态电解质膜，消耗活性锂 → 容量不可逆衰减。高温、高 SOC 长期存放会加速。
2. **析锂（Lithium Plating）**：快充/低温下锂离子来不及嵌入负极而镀在表面，既损失容量又形成枝晶（安全风险）。这是快充老化的主因。
3. 次级：活性物质剥落、电解液干涸、集流体腐蚀（高温/高 SOC 易发）。

**启示**：SOH 不是均匀下降的，而是"前慢、中快、后陡"的曲线，且**温度/SOC 使用习惯决定斜率**。BMS 的"温柔使用建议"（别总满充、别总快充、别长期高温）本质是在延缓 SEI/析锂。

## 三、SOH 估计方法

### 3.1 容量衰减法（工程主用）

思路：找一个"满充→放空"的完整循环，积分放电量 = 当前可用容量。

```
SOH_cap = Q_discharge_full / Q_nominal
```

难点：**完整充放循环在平时几乎不发生**。工程变通：
- **小循环外推**：用一段已知 ΔSOC 的放电量估算满容量 `Q ≈ ΔQ / ΔSOC`。
- **充电段统计**：快充时从 SOC_a 充到 SOC_b 的安时量 ÷ (b−a) → 容量。
- **静置 OCV 两点法**：利用 OCV 曲线上两个"陡区"电压点对应固定 SOC，期间积分电量即该 SOC 区间容量。

### 3.2 内阻法

HPPC 脉冲测 `R0(SOC)`，对比出厂/上一标定值 → SOH_r。优点可随时做（不必满放），缺点是温度耦合强，需温度归一化。

### 3.3 ICA / dV 分析（增量容量 / 差分电压）——行业硬核手段

这是本章重点。原理：**把充电电压对容量求导，得到 IC 曲线 `dQ/dV`**，曲线上的峰位置/面积对老化极其敏感。

- **ICA（Incremental Capacity）**：`dQ/dV` vs V。峰对应特定的相变反应。
- **DV（Differential Voltage）**：`dV/dQ` vs Q（放电方向），等价视角。

```python
# 示意：由充电的 (V, Q) 序列算 IC 曲线
import numpy as np
V = np.array(v_seq); Q = np.array(q_seq)
dQ = np.gradient(Q)          # 容量增量
dV = np.gradient(V)          # 电压增量
ic = dQ / dV                 # dQ/dV
# 对 ic 做高斯平滑去噪后找峰
```

**为什么牛**：老化后 IC 曲线的主峰会**左移、变矮、分裂**。通过跟踪"峰面积（对应某材料相变容量）"就能估 SOH，而且**不需要完整充放**——只要经过峰区的一小段充电数据即可，非常适合车端碎片数据。

> 坑：IC 曲线对噪声极敏感（求导放大噪声），必须平滑（高斯/小波）；且要温度/SOC 对齐，否则峰位漂移误判为老化。

### 3.4 特征工程 + 机器学习

提取健康特征（峰值面积、峰值电压、低频阻抗、容量增量等）→ 喂给 GPR/SVM/NN 回归 SOH。适合**云端**批量训练，车端只提取特征上传。

## 四、RUL（Remaining Useful Life）预测

RUL = 从当前到 SOH 跌到阈值（如 80%）还能用多久/多少里程。

- **基于模型**：拟合衰减轨迹 `SOH(t) = f(t)`（指数/多项式），外推到阈值。简单但假设衰减规律不变，突变工况下失效。
- **数据驱动**：用历史 SOH 序列做时间序列预测（ARIMA、LSTM、粒子滤波）。能学"你的使用习惯→你的衰减曲线"。
- **融合**：模型给先验、数据校正，最稳。

**工程落地**：RUL 多在**云端**做（有全车队大数据），车端只负责精准算 SOH 并上报。

---

## 五、车端 vs 云端分工

```
车端 BMS：采样 → SOC/SOH 实时估算 → 上报 SOH/特征/循环计数
                        │
                   (CAN/蜂窝上传)
                        ▼
云端：聚合全车队 → 训练老化模型 → RUL 预测 → 残值/维保/梯次利用决策
```

## 六、常见坑

1. **用额定容量算 SOH**：不做在线容量更新，SOH 永远 100% 假象。必须在线估 `Q_max`。
2. **温度不归一**：冬天内阻翻倍，内阻法 SOH 暴跌误报。内阻法须温度补偿。
3. **ICA 不平滑直接求导**：噪声被放大成假峰。务必先滤波。
4. **用一次满放标定 SOH**：一年才几次满放，SOH 长期不更新。要用小循环/充电段外推持续更新。
5. **SOH 跳变无迟滞**：SOH 应单调缓降，出现回弹是算法 bug（如容量外推区间选在噪声大的 SOC 段）。
6. **忽视不一致性**：包级 SOH 看最差单体，单体 SOH 离散度本身也是健康指标（离散度骤增 = 某芯异常）。

## 七、面试要点

- **SOH 两口径？** 容量法（Q_max/Q_nominal）与内阻法，交叉验证。
- **EOL 阈值为什么是 80%？** 行业质保/梯次利用分界，容量低于此体验与风险陡增。
- **ICA/dQ-dV 是什么、为什么好用？** 对容量求导，峰形对老化敏感，且不需完整充放，碎片数据即可估 SOH。
- **SOH 和温度什么关系？** 高温/高 SOC 加速 SEI 与析锂，老化快；估 SOH 须温度归一。
- **RUL 车端能做吗？** 多在云端，靠车队大数据+ML；车端给精准 SOH 与特征。
- **怎么缓解老化？** 避免长期满充/空电、控快充频次、控温——本质是抑制 SEI 增长与析锂。
