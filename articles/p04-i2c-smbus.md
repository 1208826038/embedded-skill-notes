# I²C 与 SMBus：开漏总线上的仲裁与电量计

## 一、场景引入：卡死的总线与被"绑架"的 SDA

某BMS 项目的样机在产线烧录后出现一个偶发故障：上电后整块板子的 I²C 总线完全不通，挂在上面的 NTC 温度传感、电量计（fuel gauge）、电源管理芯片全都没响应，I²C 控制器报"总线忙（BUSY）"且清不掉。用示波器看 SCL 和 SDA，发现 SDA 被死死拉在低电平，SCL 也是低——明显是某个从设备在中途（比如正在发送 ACK 时被意外复位）卡住了，一直把 SDA 拽着不放，成了**总线死锁（Bus Lockup）**。

恢复手段很简单却很经典：主设备不管三七二十一，在 SCL 上手动发出 9 个时钟脉冲（此时从设备会借这些时钟把没发完的位一个个推完、释放 SDA），总线就活了。这种"人质绑架"事件是 I²C 开漏结构的天生风险，也是每个底层工程师必须懂的保命技能。

理解 I²C，核心是三件事：**开漏 + 上拉实现"线与仲裁"**、**START/STOP 由 SCL 高时的 SDA 跳变定义**、以及它在 BMS 中与 **SMBus** 的紧密关系（电量计上报电压/电流/SOC 的标配）。

## 二、核心原理：开漏、上拉与"线与仲裁"

### 2.1 物理层：两线开漏

I²C 只有两根线：**SCL（时钟）**和 **SDA（数据）**。两者都是**开漏（Open-Drain）**结构——设备只能把线"拉低"或"释放"，不能主动"拉高"；线的"高"电平完全靠外部**上拉电阻**提供。

这带来一个关键特性：**线与（Wired-AND）**——只要任意一个设备拉低，整条线就是低；只有所有设备都释放，线才被上拉成高。正是这个特性，让 I²C 能在没有仲裁线的情况下实现**多主竞争**：两个主设备同时发，谁发 0 谁就把线拉低，发 1 的那方读回发现自己想发 1 却读到 0，立刻知道自己输了仲裁，自动退出发送。

### 2.2 上拉电阻取值：在上升沿与功耗间折中

上拉电阻不能随便选：

- **太大** → 上拉电流小，RC 时间常数大，SDA/SCL 上升沿过缓，速率上不去、易受噪声误判；
- **太小** → 拉低时灌电流大，功耗高，且可能超出 IO 灌电流规格。

一般按总线电容和期望上升时间算，常见 4.7kΩ（100k）到 1kΩ 量级（400k 快速模式）。这是信号完整性里最典型的"上升时间 vs 功耗"折中。

### 2.3 协议机制：START/STOP 是"特殊事件"

I²C 没有 CS，也没有独立的同步线以外的特殊信号，它靠**在 SCL 为高时让 SDA 跳变**来定义起停：

- **START**：SCL 高时，SDA 由高→低。
- **STOP**：SCL 高时，SDA 由低→高。

为什么这么设计？因为正常数据位只在 SCL **低**时变化、在 SCL 高时被采样。只有"SCL 高时 SDA 跳变"这种违反数据规则的边沿，才能被唯一地识别为起停特殊事件，绝不会和数据位混淆。

## 三、帧格式逐字段拆解

### 3.1 典型写事务（含寄存器指针）

```
START | ADDR(7)+W(0) | ACK | REG(8) | ACK | DATA(8) | ACK | ... | STOP
```

### 3.2 典型读事务（含重复起始）

```
START | ADDR+W | ACK | REG | ACK | RepeatedSTART | ADDR+R(1) | ACK | DATA | NACK | STOP
```

| 字段 | 含义 |
|------|------|
| **START** | SCL 高时 SDA 由高→低，事务开始 |
| **ADDR(7/10)+R/W** | 从设备地址（7 位常用，10 位扩展）+ 1 位方向位（0=写，1=读） |
| **ACK/NACK** | 每字节后接收方拉低 SDA=ACK；发送方发最后一字节后接收方回 NACK 表示"结束" |
| **REG** | 寄存器/命令指针（sub-address），指定读写哪个内部寄存器 |
| **DATA** | 数据字节，可连续多字节（多数器件地址自增） |
| **Repeated START** | 不释放总线再发一次 START，用于"先写寄存器再读"不被其它主设备打断 |
| **STOP** | SCL 高时 SDA 由低→高，释放总线 |

### 3.3 各字段要点

- **7 位地址空间**：0~127。0x00 是通用呼叫（General Call），0x78~0x7F 留给 10 位地址/保留，实际可用约 112 个。地址冲突是常见问题：两个同址器件挂同一总线会"打架"，需靠硬件引脚改址或每总线单一。
- **ACK 机制**：每字节后必须有 ACK，否则发送方知道从设备不在或忙。读最后一字节时主设备发 **NACK** 通知从设备"我不要再读了"，随后 STOP。
- **Repeated START（重复起始）**：I²C 读需要"先指定读哪个寄存器"。如果先写 REG、发 STOP、再发 START+ADDR+R，中间释放总线可能被别的主设备抢走。用重复起始，不释放总线再起一次，保证"写指针+读数据"原子连贯。
- **时钟拉伸（Clock Stretching）**：从设备可以**拉低 SCL** 告诉主设备"我还没准备好"，主设备必须等待。需支持拉伸的主机才能实现；不支持拉伸的主机遇到这种从设备会挂起。

### 3.4 配置代码：I²C 读一个寄存器（带重复起始）

```c
#define DEV_ADDR  0x2A   /* 7 位从地址 */

int I2C_ReadReg(uint8_t reg, uint8_t *buf, uint8_t len)
{
    /* 1) 起始 + 写地址 + 寄存器指针 */
    I2C_Start();
    if (I2C_Write((DEV_ADDR << 1) | 0) != ACK) return -1; /* ADDR+W */
    if (I2C_Write(reg) != ACK) return -1;                 /* REG 指针 */

    /* 2) 重复起始 + 读地址，连续读数 */
    I2C_RepeatedStart();
    if (I2C_Write((DEV_ADDR << 1) | 1) != ACK) return -1; /* ADDR+R */
    for (uint8_t i = 0; i < len; i++) {
        buf[i] = I2C_Read(i == (len - 1) ? NACK : ACK); /* 末字节回 NACK */
    }
    I2C_Stop();
    return 0;
}

/* 总线死锁恢复：手动发 9 个 SCL 脉冲释放 SDA */
void I2C_RecoverBus(void)
{
    GPIO_SetAsOutput(SCL_PIN);
    for (int i = 0; i < 9; i++) {
        SCL_LOW();  delay_us(5);
        SCL_HIGH(); delay_us(5);   /* 9 个脉冲，从设备借此推完剩余位 */
    }
    I2C_Start();  /* 随后发 STOP 复位状态机 */
    I2C_Stop();
}
```

## 四、SMBus：I²C 在系统管理上的"严父"

**SMBus（System Management Bus）** 基于 I²C，但定义得更严格，是电源管理、电池管理的标准。它在 I²C 基础上强化了：

- **更严格的电气与超时**：SMBus 规定超时（如 35ms / 25ms），从设备响应不能无限拖；I²C 本身没有硬超时。
- **命令码（Command）与协议**：SMBus 定义 read byte / write byte / read word / block 等标准协议，设备行为更可预期。
- **PEC（Packet Error Check，CRC-8 包差错校验）**：在帧尾附加一个 CRC-8，大幅增强可靠性。
- **BMS 强相关**：智能电池包、电量计（fuel gauge）、充电管理芯片常用 SMBus 上报电压、电流、SOC、温度，接收充放电指令。一个 SMBus 电量计把"这块电池还剩多少电、能不能放"以标准协议喂给主机，是笔记本、电动工具、车载电池模组里最常见的接口。

### 4.1 SMBus 与 I²C 的区别速查

| 维度 | I²C | SMBus |
|------|-----|-------|
| 超时 | 无硬超时 | 有（35ms/25ms） |
| 命令协议 | 自定义 | 标准化 read/write/block |
| 校验 | 仅 ACK | 可选 PEC(CRC-8) |
| 电气 | 较宽松 | 更严（电平/电流） |
| 典型场景 | 通用传感器 | 电源/电池管理 |

## 五、常见坑与调试手段

1. **上拉电阻阻值不当**：太大上升沿过缓、速率上不去且易受扰；太小功耗大、灌电流超规格。调试：示波器看 SDA/SCL 上升时间，按总线电容计算合适阻值；快速模式(400k)需更小阻值。
2. **地址冲突**：多个同址器件挂同一总线互相干扰。调试：核对每个器件地址/ADDR 引脚电平；必要时每总线单一或硬件改址。
3. **总线死锁（SDA 被从设备拉低不放）**：从设备复位异常或仲裁中途掉电导致。调试：主设备发 9 个 SCL 脉冲释放 SDA，或复位从设备；固件里加总线恢复流程，超时即触发。
4. **时钟拉伸超时未处理**：从设备拉低 SCL 不释放，主机不支持拉伸而挂起。调试：确认主机驱动支持时钟拉伸，或设超时强制恢复。
5. **重复起始处理错**：读事务中错误地先 STOP 再 START，被其它主抢走总线导致读错寄存器。调试：核对是否用了 Repeated START。
6. **电平不匹配**：3.3V MCU 接 5V 器件需电平转换，注意 5V-tolerant 输入能力，否则烧 IO 或采样错。

## 六、面试高频要点

- **I²C 为什么需要上拉电阻？** → 开漏结构只能拉低，靠上拉拉高，从而实现"线与仲裁"与多主竞争；上拉阻值决定上升时间与功耗，需折中。
- **START/STOP 为什么靠 SCL 高时的 SDA 跳变定义？** → 正常数据只在 SCL 低时变化，只有 SCL 高时 SDA 跳变才是起停特殊事件，绝不与数据位混淆。
- **总线卡死怎么恢复？** → 主设备手动给 SCL 发 9 个脉冲释放 SDA，或复位从设备；固件应加超时恢复流程。
- **为什么读要先写寄存器地址再重复起始？** → I²C 读需先指定读哪个寄存器，重复起始避免中途释放总线被其它主设备抢走，保证"写指针+读数据"原子连贯。
- **SMBus 和 I²C 什么关系？** → SMBus 基于 I²C 但更严格（超时、标准命令协议、PEC 校验、更严电气），常用于电源/电池管理；BMS 电量计常用 SMBus 上报电压/电流/SOC。
- **时钟拉伸是什么？** → 从设备拉低 SCL 告知主设备"未准备好"，主设备须等待；不支持拉伸的主机遇之会挂起。
