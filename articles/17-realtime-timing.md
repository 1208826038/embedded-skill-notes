# 实时性分析与时序：WCET、中断延迟与抖动

## 一、一个真实场景：错过一个窗口，均衡就烧了

在一款 BMS 主动均衡控制里，MCU 需要在收到电芯监控 IC（经 DSI3 菊花链）上报的压差后，于一个固定节拍内输出 PWM 驱动均衡电路。某版软件在台架高温老化时偶发"均衡开启延迟超标"——本该 1ms 内响应的控制，偶尔拖到 3ms，导致某几节电芯短时过充、温升异常。

根因不是算法慢，而是一段**长临界区**：当时为了"图省事"在均衡调度里关了全局中断去保护一个共享缓冲区，结果把 CAN 接收中断和高优先级看门狗喂狗任务都挡在了外面。高温下 Cache 命中率变化又让这段临界区的实际执行时间抖动放大。这件事让我深刻理解：实时系统的"实时"不是"平均很快"，而是"**最坏情况下也能在截止时间前完成**"。这就是 WCET 分析存在的意义。

## 二、核心原理：实时性三要素

实时性关注三个指标：

1. **WCET（Worst-Case Execution Time，最坏执行时间）**：任务在最坏条件下（Cache miss、总线被 DMA 占用、走最差输入分支、缓冲区未命中）的执行时间。它必须 **< 任务周期 / 截止时间**，否则丢帧或违约。
2. **中断延迟（Interrupt Latency）**：从中断事件发生，到中断服务程序第一条有效指令执行完毕的延迟。拆开看：
   ```
   中断延迟 = 关中断最长时间         （当前临界区/禁止中断窗口）
            + 最高优先级任务执行时间 （抢占前必须跑完的活）
            + 硬件同步/取向量开销     （NVIC 压栈、尾链等）
   ```
3. **抖动（Jitter）**：同一事件实际响应时间相对理想值的散布。抖动来源包括：长临界区、高优先级任务抢占、Cache miss、DMA 占用总线、中断嵌套重入。

类比：把实时系统想象成高铁时刻表。WCET 是"最坏天气下这趟车最晚几点到"，截止时间是"站台必须腾空的最晚时刻"。平均 30 分钟到站没有意义，只要有一次晚点超过时刻表，整条线就乱了。抖动就是"到站时间的散布"，散布越大，你得预留的缓冲越多，系统利用率越低。

## 三、关键代码与时序：如何把最坏情况"钉死"

### 1. 降低中断延迟的结构性手段

关键经验：**能用锁/互斥量就不要用关全局中断**；临界区尽量短；热路径放 TCM（紧耦合内存，1 cycle 确定延迟、不经总线争用、不进 Cache），关键数据进 DTCM。

```c
/* 反例：图省事关全局中断，挡住所有 ISR 与高优任务 */
__disable_irq();
memcpy(shared_buf, src, N);   /* N 大时，这段就是"关中断最长时间" */
__enable_irq();

/* 正例：用自旋锁/互斥量只保护共享区，且临界区极短 */
lock_acquire(&buf_lock);
shared_buf.head = new_head;   /* 仅一两句，时间可控 */
lock_release(&buf_lock);
```

### 2. 用 TCM 锁定最坏执行时间

Cortex-R/M7 的 ITCM/DTCM 访问周期固定（1 cycle），普通 SRAM 经总线可能多周期且受其他主设备争用。把中断向量表、ISR 指令（ITCM）、中断栈/高频数据（DTCM）放进去，可让 WCET 计算摆脱"总线争用"这个不确定变量。

链接脚本中划分 TCM 区域（示意）：

```ld
/* 链接脚本片段：把热路径函数钉进 ITCM */
.itcm_section (NOLOAD) :
{
  . = ALIGN(4);
  KEEP(*(.tcm_code))      /* 用 __attribute__((section(".tcm_code"))) 标记 */
} > ITCM

.dtcm_section (NOLOAD) :
{
  . = ALIGN(4);
  *(.dtcm_data)
} > DTCM
```

### 3. 中断响应时序（文字描述）

理想中断时序：外设置位中断标志 → NVIC 仲裁（若优先级更高且当前未关中断）→ 硬件自动压栈上下文（Cortex-M 约 12 cycle）→ 取向量 → 执行 ISR → 尾链（Tail-Chaining，连续中断免重复压栈）→ 出栈返回。其中"压栈+取向量"是硬开销，而"关中断最长时间+高优任务剩余时间"是软件可控变量。把后者压到最小，抖动就小。

### 4. WCET 超标时的组合拳

参考我降 CPU Loading 的实践：软件 IIC→硬件 IIC（免 CPU 位操作轮询）、全通道 DMA（ADC/SPI/UART 搬运交给硬件）、热路径进 TCM、开硬浮点 FPU（免软浮点模拟）、调编译优化 `-O2`。这些手段本质都是**减少最坏路径上的不可控耗时**。

## 四、常见坑与调试手段（至少 3 条）

1. **用平均值代替最坏值评估实时性**：示波器打 GPIO 看到"平均 0.8ms"就以为安全，忽略了那 0.1% 的 3ms 长尾。→ 必须按 WCET 评估；用逻辑分析仪/PMU 性能计数器抓取最大延迟样本，而不是看均值。
2. **长临界区导致中断"饿死"**：关中断里调了 `printf`、做了大块 `memcpy` 或等 SPI 完成。→ 临界区只留"改共享变量"的最小动作；外设等待交给 DMA/中断；对必须关中断的场景，明确预算并写注释。
3. **Cache miss 引入不可控抖动**：同一段代码冷启动时 Cache 未预热，首次执行慢数倍。→ 对确定性要求极高的 ISR，放 TCM 或预热 Cache（锁定/锁定行）；把关键数据标 non-cacheable 或进 DTCM。
4. **DMA 与 CPU 抢总线放大延迟**：大数据 DMA 搬运时 CPU 取指被 stall。→ 用 scatter-gather DMA 分块、错峰调度，或把实时任务指令锁进 TCM 使其不依赖外部总线。

## 五、面试高频要点

- **中断延迟由哪几部分组成？** → 关中断最长时间 + 最高优先级任务剩余执行时间 + 硬件同步/向量开销。
- **WCET 必须和什么比较才有意义？** → 必须小于任务周期/截止时间，否则丢帧、违约，实时性失效。
- **怎么降低中断延迟和抖动？** → 缩短临界区、用锁而非关全局中断、热路径放 TCM、避免长任务、固定 Cache 策略。
- **WCET 超标怎么办？** → 拆分任务、降低优先级干扰、TCM/编译优化、开硬浮点/DMA、提升主频。
- **时间隔离（FFI 的时间维度）是什么？** → 调度保证高 ASIL 任务有确定时间窗，低 ASIL 任务不能拖延它，是 ISO 26262 Freedom From Interference 的三隔离之一。
