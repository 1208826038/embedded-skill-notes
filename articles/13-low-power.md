# 低功耗与电源管理：休眠唤醒与 SBC/PMIC

## 一、停在车库里悄悄耗光电瓶的车

某车型静置两周后无法启动，4S 店查了一圈发现：低压电瓶被 BMS 的"微眠"吃空了——休眠电流本应 μA 级，实测却 mA 级。根因是有一个 GPIO 配成了悬空输入、一个外设时钟没关，加上 SBC 下电时序和 MCU 进低功耗的节奏没对齐，导致每次休眠都"没真正睡死"，持续漏电。

整车下电后，BMS、BCM、网关等节点必须进入**极低功耗休眠**，否则静止车辆的电瓶会被慢慢放干。低功耗不是"调一个寄存器"那么简单，而是 MCU 功耗状态、SBC/PMIC 电源时序、唤醒源配置三方协同的系统工程。

## 二、核心原理

### 2.1 MCU 的功耗状态阶梯

类比：MCU 像人睡觉，有"打盹""浅睡""深睡""昏迷"几档，越深越省电但越难叫醒。

- **Run**：全速运行，所有时钟/外设开。
- **Sleep**：内核停，但外设和 RAM 保持，总线时钟可关。
- **Stop（深睡）**：RAM 保持，大部分时钟停，仅少量唤醒源有效，唤醒后从停住处继续。
- **Standby（最低）**：仅唤醒脚/备份域有效，RAM 可能丢失，唤醒等同一次复位。

休眠目标：整车下电后 BMS 漏电极小（μA 级），同时保留"被 CAN 帧/钥匙/定时"唤醒的能力。

### 2.2 SBC / PMIC：整车电源的"总闸"

SBC（System Basis Chip，系统基础芯片）或 PMIC 不只是供电（LDO/DC-DC），还集成：

- **看门狗**（与 MCU 内部 WDT 配合或独立）；
- **唤醒源管理**（CAN 唤醒帧、IO 电平、定时）；
- **电源时序控制**（上电顺序、下电顺序）。

它相当于整车低压电源的总闸。MCU 说"我要睡"，得先跟 SBC 打个招呼，由 SBC 把外围电源掐掉，只留最小唤醒电路。

### 2.3 唤醒源：谁能把系统叫醒

- **CAN 唤醒帧**：总线上的特定帧把收发器拉醒（收发器本身在休眠期仍监听）；
- **IO 电平**：钥匙信号、充电枪插入检测；
- **定时器（RTC）**：周期性自检/上报；
- **特定中断脚**。

唤醒延迟差异是个大坑：国产替代芯片的唤醒确认往往慢于原厂，软件必须做**等待/重试补偿**，否则"醒了但还没准备好"会导致后续访问失败。

### 2.4 下电时序：MCU 与 SBC 的"交接棒"

正确下电流程应该是：

```
1. MCU 完成关键参数保存（写 NVM/FEE）
2. MCU 配置好唤醒源
3. MCU 发指令让 SBC 进入待机供电
4. MCU 自身进入 Stop/Standby
```

关键：**MCU 必须先稳稳进低功耗，SBC 再收尾断电**。

## 三、关键代码与时序

### 3.1 下电时序（正确 vs 踩坑）

```
正确：
MCU保存参数 → 配置唤醒源 → MCU进Stop → SBC延迟确认后掐外围电
                                       ↑ MCU已稳，不会被误复位

踩坑（资料实例）：
SBC 电容放电需 400us，MCU 进PWD仅 200us
→ MCU 先"睡"但 SBC 还在放电，电源跌落把 MCU 又拽醒/复位
→ 表现为偶发休眠失败、反复复位
```

修复：调时序让 MCU 先稳定进低功耗，或对 SBC 放电做**延迟确认 / 状态清理**，确保两边同时到位。双通道示波器同时抓"SBC 放电曲线"与"MCU 复位/低功耗进入信号"即可定位这个 400us vs 200us 的错配。

### 3.2 休眠前外设清理（伪代码）

```c
void Enter_DeepSleep(void) {
    Save_Critical_Params();          // SOC/标定写入FEE
    Configure_Wakeup_Sources();      // CAN唤醒/IO/RTC

    /* 关掉所有不用的时钟与外设 */
    Disable_Unused_PeripheralClocks();
    /* 未用GPIO配为确定低功耗态（非悬空） */
    for (each unused pin) GPIO_SetLowPowerMode(pin);

    SBC_RequestStandby();            // 通知SBC准备收尾
    __disable_irq();
    PWR_EnterSTOP();                 // 进Stop，WFI/WFE
    /* 唤醒后从此继续 */
    __enable_irq();
    System_RestoreAfterWakeup();
}
```

### 3.3 唤醒源判定

```c
WakeupReason = PWR_GetWakeupFlag();  // 读复位/唤醒原因寄存器
if (WakeupReason & WAKE_CAN)      Handle_CanWake();
else if (WakeupReason & WAKE_IO)  Handle_IoWake();
else if (WakeupReason & WAKE_RTC) Handle_RtcWake();
```

## 四、常见坑与调试手段

1. **休眠电流偏大（mA 而非 μA）**：总有外设时钟没关、GPIO 悬空漏电、外部上拉电阻持续耗流。调试：逐项关时钟、用电流表分段测各路漏电，定位"漏点"。

2. **SBC 下电时序错配导致复位**：如上 400us vs 200us 实例。调试：双通道示波器同时抓 SBC 放电与 MCU 进入低功耗/复位信号，调整两者节奏。

3. **唤醒失败**：唤醒源没使能、SBC 唤醒配置与 MCU 不一致、唤醒延迟未补偿（国产替代坑）。调试：先确认唤醒源寄存器配置；用信号源模拟 CAN 唤醒帧，量 SBC 有没有输出唤醒脉冲；对慢唤醒芯片加软件等待。

4. **唤醒后外设没恢复**：Stop 后时钟/PLL 复位，唤醒需重新初始化。调试：在唤醒路径补 `SystemInit()` 与外设重配，别假设"睡前后状态一致"。

5. **GPIO 悬空**：未用脚悬空既耗电又易误触发唤醒。调试：统一在初始化和休眠前把未用脚配上下拉或模拟输入。

## 五、面试高频要点

- **怎么降低休眠电流？** 关未用外设时钟、IO 配低功耗态、用 Stop/Standby、与 SBC 协同断电。
- **休眠唤醒失败一般查什么？** 唤醒源配置、SBC 时序、复位/唤醒原因寄存器、各路漏电点。
- **SBC/PMIC 除了供电还干什么？** 看门狗、唤醒源管理、电源时序控制。
- **下电时序错配的真实案例？** SBC 放电 400us 慢于 MCU 进 PWD 200us → 被误复位，示波器双路抓取定位。
- **国产替代在唤醒上有什么坑？** 唤醒源确认延迟大于原厂，需软件等待/重试补偿。
